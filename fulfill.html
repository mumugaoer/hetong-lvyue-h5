一、需求背景

合同履约管理目前仅在PC端支撑，移动端无法查看履约情况：履约负责人外出、现场等场景下无法及时掌握任务的到期时间与执行进展；合同经办人、经办负责人及分管领导无法在移动端掌握合同维度履约进度与逾期升级情况，逾期风险传递滞后。

为此，在合同管理系统移动端（H5）增加合同履约查询组件，与Web端数据同源、字段对齐、状态体系一致，支持按任务、按合同双视角查询，并提供手动确认完成等轻量操作。

上下游关系：上游为Web端履约计划维护（任务生成）及云销、招采、财务等业务系统（完成状态回写）；下游为消息中心（逾期升级通知触达）。

二、需求目标

  1. 履约任务随身可查：移动端双视角展示履约数据，状态、到期时间、剩余天数、节点进度一目了然；
  2. 轻量操作闭环：手动可完成的履约任务支持在移动端确认完成并上传附件；外部系统回写任务自动完成并明示数据来源，避免用户困惑；
  3. 完成来源双通道留痕：系统回写与手动确认均记录完成时间与数据来源，全程可追溯；
  4. 逾期升级移动可见：超期任务透明呈现升级链路与通知送达层级，支撑各级及时知悉；
  5. 端端一致：与Web端字段命名、状态分类、履约类型完全对齐，降低跨端认知成本。

三、用户角色与权限

角色 职责与权限
履约负责人 主操作角色。查看本人负责的履约任务，可执行"完成"（手动确认完成）；可切换双视角
合同经办人 主跟合同。查看经办合同的履约进度、履约记录（只读），不承担履约操作
经办负责人 日常查看本部门履约执行情况；任务逾期时接收升级知会（消息中心触达）
分管领导/公司分管领导 基于逾期升级通知查看，掌握逾期风险与处置进展

权限原则：双视角页签不绑定角色；数据可见范围由行级数据权限控制——履约负责人可见本人负责任务及所属合同，经办人可见本人经办合同，经办负责人及以上按数据权限逐级放大。

四、名词解释

名词 解释 备注
履约任务 履约计划拆分的最小执行单元，含计划完成时间与责任人 按任务视角的操作对象
履约节点 合同维度下履约任务的展示口径 履约记录按计划完成时间倒序
履约类型 六类枚举：应付账款、应收账款、接受货物或服务、提供货物或劳务、发票开具、其他 与Web端字典一致
数据来源 任务所属外部业务系统：云销系统、招采系统；为空表示本系统录入 与Web端字典一致
已超期 / 已终止 已超期：超过到期时间未完成的进行中任务；已终止：因合同变更等原因终止的履约计划 已终止需展示终止说明与终止人
工作进度 / 资金进度 已完成节点数（金额）占节点总数（总金额）的百分比 分别为绿色/蓝色进度条
剩余天数 履约到期时间与当前日期的差值 正数"还剩N天"（绿色），负数"逾期N天"（红色）

五、功能详细需求

5.1 双视图切换

项目 内容
用户场景 履约负责人以任务为作业单元日常跟进，合同经办人以合同为主线掌握整体进度
功能说明 组件顶部提供「按任务查询」「按合同查询」两个页签，默认进入「按任务查询」；切换不刷新页面，本地过滤视图
目标用户 全部角色
界面原型 在线原型-顶部视图页签
业务规则 1. 页签不绑定角色，人人可切换
2. 数据可见范围由行级数据权限控制，与页签无关

5.2 履约任务列表（按任务视角）

项目 内容
用户场景 履约负责人打开组件即查看本人履约任务全景，按状态快速过滤，定位待办与超期风险
功能说明 页面结构：容器导航栏（返回/标题/更多）→搜索框（右侧筛选入口）→视图页签→任务状态页签→任务卡片列表。从工作台直入，无底部TabBar与页脚标语；状态页签横向滑动
目标用户 履约负责人、经办负责人、分管领导
界面原型 在线原型-任务状态页签与任务卡片列表
业务规则 1. 状态分类与Web端一致：全部、未开始、进行中、已超期、已完成、已终止，页签带计数
2. 默认展示"全部"，按剩余天数升序排列（最紧急在前）
3. 剩余天数=履约到期时间-当前日期，正数显示"还剩N天"（绿色）、负数显示"逾期N天"（红色）并转入已超期状态
4. 任务卡按状态差异化展示：进行中显示剩余天数与节点摘要；已超期显示升级链路；已终止显示终止说明与终止人；已完成显示完成时间与数据来源
5. 已终止任务随合同变更处理，由Web端履约计划维护按变更结果重建或恢复，移动端同步展示
6. 任务卡按完成方式区分（色块标识直观区分）：本系统录入任务标识「手动完成」（橙色）、展示「完成」按钮（见5.4）；外部系统来源任务标识「系统完成」（蓝色）、展示数据来源，由业务系统回写完成状态，不展示「完成」按钮
7. 页面入口：工作台常用功能宫格、待处理任务统计卡、今日待办提示条三处进入，导航栏返回箭头回到工作台

5.4 完成确认

项目 内容
用户场景 履约负责人完成履约内容核验后，在移动端确认完成并上传凭证附件（验收单、结算单、发票等）
功能说明 底部弹窗：履约计划参考附件查看区（履约计划维护时上传，只读）+ 完成凭证附件上传区 +「确认完成」「取消」
目标用户 履约负责人
界面原型 在线原型-完成确认底部弹窗
业务规则 1. 附件为可选项，无附件可直接确认完成
2. 上传限制：word/jpg/png/PDF，单个≤50M，最多10个
3. 确认后任务状态即时更新为"已完成"，完成时间取系统当前时间
4. 已超期任务完成后，升级链路自动终止后续通知
5. 弹窗内展示履约计划已有附件供核对，移动端只读；如需上传或替换计划附件请到PC端操作

输入输出字段：

字段名 字段类型 字段逻辑 输入/输出 备注
履约计划参考附件 文件列表 履约计划维护时上传的参考附件 输出 只读查看，与完成凭证区分
完成附件 文件 可选，支持多文件上传 输入 限制见业务规则
完成时间 日期 提交时取系统当前时间 输出 自动记录
任务状态 枚举 提交后更新为已完成 输出 同步刷新列表

5.5 逾期升级展示

项目 内容
用户场景 任务超期后按升级链路逐级通知：履约负责人→经办人→经办负责人→分管领导→公司分管领导，各级基于通知进入组件查看逾期时长与送达层级
功能说明 已超期任务卡展示红色逾期天数，右侧蓝色「查看记录」点击展开/收起送达明细（时间+层级）；超期节点详情同步展示送达记录；升级记录时间轴完整形态随跟进记录能力二期提供
目标用户 经办负责人、分管领导、公司分管领导
界面原型 在线原型-已超期任务卡升级链路横幅
业务规则 1. 超期后触发升级通知，经消息中心推送，本组件只呈现送达层级，不重复建设通知列表
2. 升级时点按预期通知机制执行
3. 任务完成后升级链路自动终止

5.6 合同履约列表（按合同视角）

功能说明 底部弹窗：合同概要（名称、状态、编号、金额、经办人、履约期限、节点统计、双进度）+ 履约节点时间轴

2. 每个节点行展示：履约类型徽标、节点名称、状态标签、计划完成时间
3. 时间轴连接线统一主题色，节点状态由圆点与状态标签表达
4. 节点详情按状态差异化展示：已完成节点含完成时间、完成方式（系统完成/手动确认上传附件）、完成凭证附件；未开始/进行中节点展示履约计划相关附件；超期节点展示升级通知送达记录

5.8 合同文本与附件（二期）

项目 内容
用户场景 履约负责人现场核验需对照合同条款，经办人需查阅补充协议
功能说明 底部弹窗展示合同归档库附件清单：文件图标、文件名、大小、归档版本、在线预览入口
目标用户 全部角色（按数据权限）
界面原型 二期实现
业务规则 1. 附件来源于合同归档库，移动端只读、支持在线预览，不支持上传与下载到本地
2. 附件类型含合同正文（用印版）、补充协议、技术协议、报价明细单等，以归档库实际版本为准
3. 归档库文件更新后移动端实时可见

六、非功能需求

  1. 端端一致性：字段命名、状态分类、履约类型枚举（六类）、数据来源枚举、剩余天数文案均与Web端对齐，依据Web端源码逐项校准；
  2. 数据同源：移动端与Web端读取同一履约数据服务，状态变更实时同步PC端；
  3. 性能：列表首屏加载≤2秒，状态过滤、页签切换本地完成；
  4. 安全：数据行级权限控制；附件仅在线预览不落地；遵循公司信息安全规范；
  5. 兼容性：适配主流移动端浏览器与企业微信/门户容器，页签横向滑动兼容iOS橡皮筋效果。
